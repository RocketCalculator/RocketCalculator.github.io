# Developer guide

Everything you need to work on Rocket Calculator: setting up, how the code is organised, how to add or change a
calculator, and the checks that run before a pull request is merged. Start with [CONTRIBUTING.md](../CONTRIBUTING.md)
for the rules.

## Setup

You need **Node 22** and **Python 3**. For the browser checks you also need a Chromium-based browser.

```sh
git clone https://github.com/RocketCalculator/RocketCalculator.github.io.git
cd RocketCalculator.github.io
npm ci                 # installs puppeteer-core (browser checks only; the site itself has no dependencies)
npm run serve          # the site at http://localhost:8000
npm test               # the full test suite (about 8 minutes)
```

There is no build step: `site/` is the website exactly as GitHub Pages serves it. Edit a file and reload.

For the browser checks, point them at a Chromium binary and the running site:

```sh
export CHROME=/path/to/chrome BASE=http://127.0.0.1:8000/
```

## How the code is organised

```text
site/
  index.html, about.html, 404.html, sitemap.xml, robots.txt
  calculators/<slug>.html   page shells, generated by scripts/generate_pages.mjs
  docs/<slug>.html          theory pages, written by hand
  references/               the reference library (PDFs + references.json)
  css/site.css              all styles; design tokens at the top
  js/
    calc/                   physics: plain functions, no DOM, imported by the tests
    calculators/<slug>.js   one definition per calculator (fields, compute, verdict, plots, drawing, info texts)
    calculator-page.js      the shared page that renders any definition
    ui/                     shared components: form, chart, drawing viewport, report, drawer, tour, export
    app.js, home.js, …      site shell (header, footer, search) and the other pages
    registry.json           areas, topics and calculators, generated by scripts/seed_registry.py
tests/                      node --test files: source examples, workbook comparisons, invariants, random sweeps
scripts/                    page generator, SEO, extraction pipeline, browser test runners
data/, derived/, source/    the original reports and workbooks and what was extracted from them (see THIRD-PARTY.md)
```

A calculator is **one definition module** (`site/js/calculators/<slug>.js`) plus its physics in `site/js/calc/`. The
shared page does the rest, so every calculator behaves the same way. The definition API and the shared components are
described in [KNOWLEDGE.md](../KNOWLEDGE.md) (*Shared component reference*). What a calculator page must contain is in
[CALCULATOR-SPEC.md](CALCULATOR-SPEC.md); the visual rules are in [DESIGN-GUIDE.md](DESIGN-GUIDE.md).

## Adding a calculator

1. Open a *Feature* issue and wait for `status: accepted`.
2. Write the physics in `site/js/calc/<name>.js` with tests in `tests/<name>.test.js` that reproduce the source's
   worked example (every printed intermediate) or the workbook's cached values.
3. Write the definition in `site/js/calculators/<slug>.js`, following CALCULATOR-SPEC (inputs grouped in fill order
   and bounded, verdict with solved fixes, key results, a drawing to scale, plots, info texts, report).
4. Register it in `CALCULATORS` in `scripts/seed_registry.py`, then generate the pages and the SEO metadata:

   ```sh
   python3 scripts/seed_registry.py && node scripts/generate_pages.mjs && node scripts/seo.mjs
   ```

5. Write the theory page `site/docs/<slug>.html` (copy an existing one), then run `node scripts/seo.mjs` again.
6. Record sources and lessons in KNOWLEDGE.md, judgement calls in DECISIONS.md, and add a CHANGELOG entry.

## Checks before a pull request

CI runs `npm test` on every pull request; it must pass. Before you open the pull request, also run the checks that
fit your change (the full list is [CALCULATOR-SPEC §9](CALCULATOR-SPEC.md#9-testing-a-calculator-before-every-merge)):

| Check | Command | When |
|---|---|---|
| Unit tests | `npm test` (or `node --test --test-name-pattern "<slug>" tests/aggressive.test.js` while iterating) | Always |
| Slider sweep | `node scripts/sweep.mjs <slug>` | A calculator changed |
| Layout stability | `npm run test:ui-layout -- --only <slug> --widths 390,1280` | Anything visible changed |
| Drawings | `npm run test:ui-diagrams -- --only <slug>` | A drawing changed |
| Random inputs | `node scripts/uifuzz.mjs <slug>` | A calculator changed |
| Every page | `node scripts/smoke.mjs site` | Shared code, CSS or pages changed |
| SEO and sitemap | `node scripts/seo.mjs` then `node --test tests/seo.test.js` | A page was added, renamed or retitled |

Then **look at it**: screenshots at 390 and 1280 px, light and dark, of what you changed, attached to the pull
request. On a touch screen, check that a vertical swipe anywhere scrolls the page and nothing changes by accident.

## Code style

- Vanilla ES modules, no framework and no build step. A new runtime dependency needs an accepted issue.
- Match the surrounding code: its naming, density and idiom. Two-space indentation (see `.editorconfig`).
- Physics functions are pure and take SI or the source's native units, stated at the top of the module.
- Comments explain *why*. Cite the source (report, equation, page) next to every formula.
- Accessibility: every control has a label, works from the keyboard, and does not rely on colour alone.

## Deploying and releasing

Merging to `main` deploys the site through [.github/workflows/pages.yml](../.github/workflows/pages.yml), which also
refreshes the sitemap dates and stamps every module with a content hash so browsers never mix old and new files.
Releases (version tags and GitHub Releases) are described in [GOVERNANCE.md](../GOVERNANCE.md#releases).
